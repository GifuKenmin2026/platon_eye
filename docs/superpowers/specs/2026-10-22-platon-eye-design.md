# プラトンの眼（Ὁ ὀφθαλμὸς τοῦ Πλάτωνος）— 設計書

> 日付：2026-10-22
> 締切：2026-10-29（1週間）
> 目標：展示でシステムとして通しで動くこと

## 1. 目的

日常の物を撮ると、写真の中の物がモザイクで覆われ、その物が分有する「イデア」の1語と辞書風の定義が現れる。
来場者は結果を図鑑（巻物）に収めるか選ぶ。図鑑は来場者みんなの分がたまっていく。

モードは2つ。最初のタイトル画面で選ぶ。
- 観測（通常）：自由に撮って、イデアを集める
- 探究（ゲーム）：お題のイデアを分有する物を、90秒以内に探して撮る

評価軸（ヒーローズ・リーグ）
- チャレンジ度：プラトン哲学。物質が消え、概念だけが残る引き算の表現
- ギーク度：Gemini の輪郭検出 ＋ OpenCV の背景補完パイプライン
- ワクワク感：撮る → 読む → 集める の繰り返し

## 2. 前提

ユーザーが決めたこと
- 撮影 → 分析中 → 結果（元写真｜イデア写真、定義、「保存しますか？」）
- はい → 図鑑へ。いいえ → 撮影画面へ
- 単語はプラトンのイデア論にもとづく名詞1語。皮肉・冗談なし
- 機材：Windows PC、USBカメラ（プラトン像の頭の中）、PCモニター、マウスとキーボード
- 消える瞬間のアニメーションなし
- 見た目はパピルス風。ギリシャ語のタイトルを添える
- 図鑑は全員分がたまる。カードを押すと詳しく見られる
- 探究モード：お題1つ、制限90秒、時間内なら何度でも撮り直せる
- 探究の判定：Gemini が「この物はお題のイデアを分有しているか」を判定し、理由も出す
- お題は用意した一覧から出す（編集できるファイル）
- 探究のランキング：お題ごとに速い順5件。名前なし。秒数と物の小さい写真
- 観測と探究は入口（タイトル画面）だけ分ける。図鑑は共通。探究で当てた物も「保存しますか？」で図鑑に入れられ、カードに印がつく

仮定（変える場合は申し出る）
- 展示PCはインターネットにつながる
- APIキーが無い間は「お試しモード」で全部の流れが動く
- Gemini のモデルは `gemini-3.8-flash`（2.5系は2026年10月に終了済み）。`.env` で変えられる

## 3. 方式

PC上で Python の小さなサーバーを動かし、ブラウザで画面を開く。

- サーバーは標準ライブラリ（`http.server`、`urllib`）＋ OpenCV ＋ NumPy だけ
- Gemini は REST で直接呼ぶ（公式SDKを入れない）。APIキーはサーバー側だけが持つ
- カメラはブラウザの `getUserMedia` で読む（`localhost` は安全な場所あつかいなので許可される）
- 図鑑はブラウザの IndexedDB に保存

不採用：FastAPI＋公式SDK（入れる物が多く Windows で詰まりやすい）、全部ブラウザ（APIキーが露出、処理が重い）

## 5. 処理の流れ

```
[ブラウザ] カメラ映像 ─Space─▶ JPEG（長辺1600まで）
   │ POST /api/transmute（本文＝JPEG）
   ▼
[サーバー pipeline.transmute]
   1. 縮小版（長辺1024）を作る
   2. gemini.segment   … 主役の物体を1つ選び {box_2d, mask(ポリゴン), label}
        失敗・空 → target=None
   3. vision.erase_object
        マスク：ポリゴン → 無ければ GrabCut(ボックス) → 無ければ GrabCut(画面中央)
        マスクを少し太らせる
        範囲：輪郭と物を囲む四角を合わせ、少し広げた四角（輪郭が一部しか取れなくても物全体を覆う）
        モザイク：範囲の中をマスで塗り分ける（マスは物の長い辺の 1/12、最小 16px）
        文字の位置：範囲の中央
   4. gemini.idealize … {word, reading, greek, greek_reading, definition, participation}
   5. JSON で返す
   ▼
[ブラウザ] compose.js が消えた場所に単語を白い明朝で描く → 結果画面
   はい → db.js に保存 → 図鑑（新しいカードを目立たせる）
   いいえ → 撮影画面
```

お試しモード：2 を飛ばし、3 は GrabCut(画面中央)、4 は demo_ideas からランダム。

### 探究モードの流れ

```
タイトル ─2─▶ お題画面【庇護】＋上位5件 ─Space─▶ 探す（残り90秒、カメラ映像の上にお題と残り秒）
                                                    │ Space（撮影）
                                                    ▼
                         POST /api/transmute?quest=庇護 → 分析中（残り秒は減り続ける）
                                                    │
                     ┌─ はずれ：物のイデアと「なぜ分有していないか」→ Space でまた探す
                     └─ 当たり：達成画面（○秒・○位）→ 記録を残す → 保存しますか？
                                 はい → 図鑑（印つき） / いいえ → タイトル
  残り0秒（分析中でない時）→ 時間切れ画面（当たりの例）→ 何かキーでタイトル
```

- 時間はお題画面で Space を押した瞬間から数える
- 判定はシャッターを押した時の残り時間で決める。押した時に残りがあれば、分析中に0になっても当たりは有効。秒数はシャッターまでの時間
- お題は前回と同じ語を避けてランダムに選ぶ
- 制限時間は 90秒。確認用に URL の `?limit=5` で短くできる
- 判定はイデア生成と同じ1回の Gemini 通信で行う（待ち時間は増えない）

## 6. API

`GET /api/status` → `{"mode": "gemini"|"demo", "model": "gemini-3.8-flash"}`

`POST /api/transmute`（Content-Type: image/jpeg、20MB まで）

成功：
```json
{
  "ok": true,
  "mode": "gemini",
  "label": "エナジードリンクの缶",
  "idea": {
    "word": "活力", "reading": "かつりょく",
    "greek": "ἐνέργεια", "greek_reading": "エネルゲイア",
    "definition": "可能なものを現実のはたらきへと移し、生きるものを内側から動かす力そのもの。",
    "participation": "このエナジードリンクの缶は、活力を分有している。"
  },
  "anchor": {"cx": 0.5, "cy": 0.42, "w": 0.14, "h": 0.58},
  "mask_method": "gemini-polygon",
  "original": "data:image/jpeg;base64,...",
  "erased": "data:image/jpeg;base64,...",
  "seconds": 7.2
}
```
`anchor` は画像に対する割合（0〜1）。`mask_method` は `gemini-polygon` / `gemini-png` / `grabcut-box` / `grabcut-center`。

失敗：`{"ok": false, "error": "日本語の説明"}`（HTTP 400 または 500）

探究モード：`POST /api/transmute?quest=<お題の語>`（URL エンコード、20文字まで）
成功時の JSON に次が加わる。
```json
"quest": {"word": "庇護", "match": true, "reason": "雨や寒さから身を包み守るはたらきを持つため。"}
```
`quest` を付けない時はこの項目は無い。

## 7. Gemini の使い方

- エンドポイント：`/v1beta/models/{model}:generateContent`。失敗したら `/v1beta/interactions` で再試行
- 輪郭：構造化出力（`box_2d` は `[ymin,xmin,ymax,xmax]` 0〜1000、`mask` は `[x,y]` のポリゴン 0〜1000）。思考は `minimal`。400 が返れば思考設定を外して再試行
- ポリゴンの座標が「画像全体基準」か「ボックス内基準」か揺れるので、両方で描きボックスとの重なり（IoU）が大きい方を採用。0.3 未満なら使わない
- 旧形式（base64 PNG）のマスクも読める
- イデアのプロンプト：イデア論の説明（分有）を与え、物体の名前・ブランドではなく本質を名詞1語で。定義は国語辞典の語釈の文体、40〜70字、皮肉なし、物体名を出さない
- 401/403 は「APIキーが無効」として画面に出す
- 探究の判定：お題があるときだけ、イデアのスキーマに `quest_match`（真偽）と `quest_reason`（30〜50字）を足す。
  プロンプト：「この物は『{お題}』のイデアを分有しているか。物の本来のはたらき・あり方が、そのイデアに確かに与っているときだけ真。こじつけは偽」
- お試しモードの判定：半分の確率で当たり。理由は「お試しモードのため判定は無作為です。」

## 8. 画面

同時に見えるのは1つ（詳しい表示だけは図鑑の上に重なる）。

共通
| 画面 | 中身 | キー |
|---|---|---|
| タイトル | 碑文風タイトル、「観測」「探究」「図鑑」の3つの入口、カメラ選択 | 1 観測、2 探究、Z 図鑑 |
| 分析中 | 撮った写真を薄く、上に「分析中…」。動きなし（探究では残り秒も） | なし |
| 図鑑（巻物） | 横に長い巻物にカードが段で並ぶ。収蔵数。全部消す | ←→ ホイール 移動、Esc タイトルへ |
| 詳しい表示 | 大きなイデア写真、元写真、定義、分有の文、日時、（探究なら印と秒数）、削除 | Esc 閉じる |
| エラー | 何が起きたか、どうすればよいか | 何かキー → タイトルへ（探究中は探す画面へ戻り、時間は減り続ける） |

観測モード
| 画面 | 中身 | キー |
|---|---|---|
| 撮影 | カメラ映像、撮影ボタン、図鑑ボタン | Space/Enter 撮影、Z 図鑑、Esc タイトル |
| 結果 | 元写真｜イデア写真、定義の札、「保存しますか？」はい／いいえ | Y はい → 図鑑、N いいえ → 撮影 |

探究モード
| 画面 | 中身 | キー |
|---|---|---|
| お題 | 大きなお題【庇護】、読み、ギリシャ語、「これを分有する物を探せ」、そのお題の上位5件 | Space 始める、Esc タイトル |
| 探す | カメラ映像の上にお題と残り秒（数字だけ変わる） | Space/Enter 撮影、Esc やめる（確認なし、記録なし） |
| はずれ | 元写真｜イデア写真、物のイデア、「分有していない」理由、残り秒 | Space また探す |
| 達成 | 元写真｜イデア写真、「探究達成」、秒数、順位、理由、定義、「保存しますか？」 | Y はい → 図鑑、N いいえ → タイトル |
| 時間切れ | 「時間切れ」、お題、当たりの例（quests.json の例） | 何かキー → タイトル |

`quests.json` の形
```json
[{"word": "庇護", "reading": "ひご", "greek": "σκέπη", "examples": ["上着", "傘", "帽子"]}]
```
20語ほど。展示会場や持ち物で見つかる語にする。

見た目
- 色：紙 `#D8C690`、繊維 `#B49E64`、墨 `#2B2218`、朱 `#8A2A1B`（見出し）、エジプシャンブルー `#2D5B8E`（選択中のボタンとキーボードの焦点だけ）
- 文字：日本語 Shippori Mincho、ギリシャ語 GFS Didot（Google Fonts。つながらなければ Yu Mincho などに切り替え）
- タイトル：碑文風の大文字 `Ο ΟΦΘΑΛΜΟΣ ΤΟΥ ΠΛΑΤΩΝΟΣ`、下に「プラトンの眼」
- 飾りは巻物の端と繊維の筋（CSS と SVG のノイズで作る。画像ファイルなし）だけ
- 動きは押した時の反応だけ

イデアの単語の描き方（compose.js）
- 白、明朝、やわらかい影
- 大きさ：`min(画像の短辺 × 0.22, 物の幅 × 0.9 ÷ 文字数, 物の高さ × 0.6)`、最小は短辺 × 0.06
- 位置：`anchor` の中心
- 描いた画像を JPEG にして保存に使う

カメラ
- 選んだカメラは localStorage に覚える
- 解像度は 1280×720 を希望
- カメラが無い・許可されない → エラー画面に直し方を書く

## 9. 保存（IndexedDB）

DB `platon-eye`、ストア `ideas`（自動番号）

```
{ id, createdAt, word, reading, greek, greekReading, definition, participation,
  label, mode, idea: Blob(JPEG), original: Blob(JPEG),
  questWord?, questSeconds? }        ← 探究で当てて保存した時だけ
```

ストア `records`（探究のランキング、自動番号、`word` に索引）

```
{ id, createdAt, word, seconds, thumb: Blob(JPEG 長辺240) }
```

- 1件ずつ削除できる（確認あり）
- 全部消す（確認あり）。ランキングは消さない。ランキングを消すのはタイトル画面で Shift+Delete（確認あり）
- 同じ単語が何度出ても別のカードとして残す
- ランキングは当たった時に自動で残す（図鑑への保存とは別）。順位は秒数の小さい順、同じなら先に出した方が上

## 10. エラーの扱い

- Gemini の輪郭が失敗 → GrabCut で続ける（結果は出る）
- Gemini のイデアが失敗 → エラー画面「イデアを取り出せませんでした。もう一度撮ってください」＋理由
- APIキー無効 → エラー画面に `.env` の直し方
- ネットにつながらない → エラー画面「インターネットにつながっていません」
- サーバーが落ちている → エラー画面「サーバーが動いていません。start.bat を起動してください」
- 時間切れ：輪郭 45秒、イデア 60秒
- 展示中はサーバーを止めない（例外はログに出して 500 で返す）
- 探究中のエラー：エラーを見せ、何かキーで探す画面へ戻る。時間は止めない。分析中でない時に0秒なら時間切れ画面へ
- quests.json が読めない・空：探究の入口に「お題の一覧を読み込めません」と出し、観測だけ使える

目標時間：撮影から結果まで 15秒以内（画像処理は 1秒以内）

## 11. テスト

Python（`python -m unittest`、追加ライブラリなし）
- vision：合成画像で、ポリゴン／ボックスだけ／何もなし の3通り。マスクが物の場所を覆うこと、補完後に物の色が残らないこと、処理が1秒以内なこと
- vision：ポリゴンの2つの座標基準を正しく見分けること。壊れた入力で落ちないこと
- gemini：`_post` を差し替えて、応答の読み取り、思考設定を外す再試行、interactions への切り替え、401 の扱い
- gemini：お題ありの時だけスキーマとプロンプトに判定が入り、`quest` が返ること
- pipeline：お試しモードで1枚を通し、API の形どおりの JSON が返ること。`quest` あり／なし両方
- app：サーバーを立てて `/api/status`、`/api/transmute`（`?quest=` あり／なし、長すぎるお題は 400）、静的ファイル、存在しないパスの 404

画面
- 開発環境のヘッドレスブラウザで、偽のカメラ映像を使って次を通す。各画面のスクリーンショットを目で確認
  - 観測：タイトル → 撮影 → 結果 → 保存 → 図鑑 → 詳しい表示
  - 探究：タイトル → お題 → 探す → はずれ → 当たり → 達成 → 保存 → 図鑑（印）、時間切れ（時間を短くして確認）
- 残り時間の計算（シャッター時の残りで判定）は quest.js の純粋な関数にして、ブラウザ内の小さなテストで確かめる
- 本物の USB カメラと Gemini は、ユーザーの Windows PC で確認（README に手順）

## 12. やらないこと

- 消える瞬間のアニメーション、効果音
- 日本語以外の画面
- クラウドへの保存、複数PCの同期
- 管理画面（削除と全部消すだけ）
- 探究のヒント、難易度、名前入力、複数人の対戦

## 13. 試作コードについて

この設計の前に `server/vision.py`、`gemini.py`、`demo_ideas.py`、`app.py` を試作した。
背景補完は合成画像で 1 枚 0.4 秒で動いた。実装計画では、これを参考にしつつ、テストを先に書いて作り直す。
